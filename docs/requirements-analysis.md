# 需求分析：QNX IPC Security Lab

文档ID：RA-001，版本0.1，2026-10-22首轮提交评审稿。基线为17a4a3776080247ec7e19fe3ab3b05a9b787edd9及本轮文档差异。本文是需求来源与取舍分析；可执行行为以[规格说明](specification.md)为准。教师已同意选题（用户转述），本文不代替正式规格确认或最终验收。

## 问题与建设目标

QNX资源管理器通过消息处理客户端操作。仅观察一次请求是否返回错误，不能回答非法输入是否被防御层阻断、目标是否真正收到请求、超时是否意味着进程退出等问题。本项目以授权自建的/dev/ipcsec-lab为对象，建立合法通信、有限变异、客户端策略、独立接收审计和限定恢复的可重复流程。

目标是使每个结论能够对应具体输入、策略、后端及源码身份，支持教师检查和伙伴接管。课程目标以工程实现和证据可复核为主；本科毕设升级为后续建议，不计入当前交付承诺。

## 场景、风险与需求推导

| 场景/风险 | 需要的能力 | 需求及优先级 |
| --- | --- | --- |
| 错目标、撤权后仍发请求 | 登记范围、逐请求授权及关闭失败路径 | SEC-01，必须 |
| 合法输入也不能稳定完成 | ECHO已知应答与合法基线 | IPC-01，必须 |
| 手工输入无法复核边界 | 固定种子、三类变异、保存和重放 | FUZ-01，必须 |
| 长度、类型等非法输入进入目标 | 应用路径校验及拒绝不转发证明 | SEC-03，必须 |
| 连续有效请求消耗资源 | 有界会话窗口及拒绝不计数 | SEC-04，必须 |
| 混用模拟和原生证据或版本 | 用例/结果/manifest与独立审计关联 | OBS-01，必须 |
| 将超时说成崩溃或隔离成功 | 分类观测及缺失证据报告未知 | ISO-01，必须 |
| 作者能运行但伙伴不能接管 | 启动、重放、重置、恢复说明及伙伴验证 | REL-01，必须；伙伴完成状态另列 |

主要资产为自建设备、运行配置、授权文件、测试语料和证据。信任边界包括主机与Guest、客户端与资源管理器、原始记录与评价器。会话编号和私有授权文本属于实验输入，不是认证凭证；可直接访问设备的程序能绕过客户端网关。模型输出是建议，不拥有批准或签署权限。

## 典型用例

UC-01：作者启动已登记自建服务，发送合法ping和空载荷，核对返回及目标接收记录（IPC-01、OBS-01）。

UC-02：固定同一语料，分别执行baseline与defense；前者保留范围控制，后者增加字段检查与会话限流；核对拒绝请求未到达目标（SEC-01/03/04、FUZ-01）。

UC-03：监督进程按逐请求握手更改本轮私有授权文件；撤权确认后的请求拒绝，重新授权后恢复；不承诺取消在途IPC（SEC-01）。

UC-04：只对本轮子进程受控退出/暂停，分别观测退出、发送侧超时和恢复，缺完整系统服务探针时报告INCONCLUSIVE（ISO-01、REL-01）。

UC-05：伙伴按手册在授权环境生成新证据并独立解释限制，作者自检不替代此事件（REL-01）。

## 约束、非目标与质量要求

仅测试本机授权VM内自建目标；不测试系统服务和第三方目标，不承诺全系统透明MsgSend拦截、漏洞崩溃发现或生产级隔离。主机Python标准库模拟用于流程校验，C/QNX原生用于真实IPC；二者不能静默替代。

协议合法payload最多64字节；畸形输入实际最多65字节，不能依不可信声明长度分配内存。原生常规批次默认128、最多200；每次IPC 2秒、监督15秒、主机45秒。专用场景预算见Harness。保留失败、版本和哈希；哈希提供完整性核对，不证明真实性或独立复现。性能阈值和正式Trial数待冻结，不编造指标。

## 可行性与取舍

QNX8 x86_64工具链、VM、合法devctl及限定原生实验已有历史记录，起步可行性已解除；新会话仍需核对环境。选择自建资源管理器及客户端应用网关以控制目标和恢复成本，接受可绕过与覆盖有限的代价（ADR0001）。只计放行请求解决两后端计数差异（ADR0003）。评价器与执行链路解耦，真实材料门未通过时保留人工复核（ADR0002）。
