# 本科毕设升级建议：有状态IPC测试与防御验证

性质：2026-10-19规划建议，需与毕设导师确认题目、工作量及最终验收；不改变当前实验授权或默认配置，不自动开始新范围测试。

## 建议题目与研究问题

《面向QNX资源管理器的有状态IPC接口测试与防御验证方法设计与实现》。以可复现工程方法和对照实验为主，是否满足本校创新要求由导师确定，不预先宣称算法创新。

主线选择一个：在相同测试预算下，利用协议结构和状态反馈的序列生成，是否比随机字段变异更有效地发现可复核的状态/权限错误？次级问题：关键检查移到自建服务端或受权限约束的通信路径后，能否防止绕过客户端网关，同时维持可接受开销？

当前单次ECHO、固定变异与恢复机制是工程基础；不能仅靠增加页面、模型或测试条数回答研究问题。LLM证据审查作为附属工具保留，不必成为第二个研究主线。

## 三个重点

1. **有状态目标与序列模型**：在自建服务中增加最小会话状态（如创建、写入、提交、关闭），明确不变量、授权变化边界与跨会话隔离。先画模型并建立独立oracle，再实现及生成序列，避免模型与实现共享同一错误。先用小序列预算，不直接扩至系统服务。
2. **可测的反馈生成**：比较随机变异、结构感知变异、状态反馈序列三种策略。记录到达状态、状态转换和唯一缺陷；只有获得真实插桩覆盖才称代码覆盖。先验证QNX工具链插桩可行性；不支持时采用显式状态/分支反馈，并如实命名。主机抽取纯解析模块进行coverage-guided fuzzing是候选补充，不冒充QNX原生覆盖。
3. **防御位置与绕过验证**：当前客户端网关可绕过。候选升级为服务端关键策略或受设备访问控制约束的独立代理，验证直接设备访问者是否仍能违反策略。身份不能只信任客户端session标签。基于QNX官方访问控制与procmgr abilities设计最小权限，先做小型可行性验证，不承诺全系统透明拦截。

## 实验建议

| 实验 | 固定条件 | 主要观察 |
| --- | --- | --- |
| 生成策略对照 | 同目标版本、独立种子组、预算、初始状态、oracle | 状态/转换覆盖、发现已知缺陷比例、首次发现时间、吞吐 |
| 反馈消融 | 同生成器与配置，逐项关闭状态反馈或语料保留 | 增量收益与开销，允许无收益 |
| 防御位置对照 | 同请求/序列，分别测试客户端路径与直接访问路径 | 非法转发、非法接受、授权拒绝、正常策略限流及真正误拒分列 |
| 有界恢复 | 固定自建进程故障方式与观测窗口 | 故障、超时、监督失败、恢复成功、未知分列及恢复耗时 |

先预实验估算每轮时间和资源，再前瞻冻结重复次数、种子与停止条件。随机策略需多个独立Trial，报告分布及不确定性，不能只选最好一次；具体次数由预算与统计目的确定，不把建议次数写成课程硬要求。性能报告同时给样本数和测量范围，不凭少量数据宣称P99达标。

可构建带明确标注缺陷的教学版本，用隐藏缺陷集检验检出能力；区分构造缺陷、意外真实缺陷、去重后根因。缺陷集不能全部暴露给生成策略后再声称泛化；保留独立验证目标或留出缺陷。发现教学缺陷无需声称发现QNX内核漏洞或CVE。

修正现有false_positive_rate语义：合法但按策略应限流的拒绝不是误报。分别报告结构合法输入拒绝、预期限流、撤权拒绝与策略错误拒绝，分母和oracle提前冻结；旧历史summary保持原样，在新指标版本中解释。

## 建议节奏与成果

建议按约8至12周可调整计划：先用1至2周完成课程收尾、冻结基线和文献/开题；2至3周建立状态模型、独立oracle和可复核缺陷集；2至3周实现一项主方法及最小权限可行性验证；2至3周做固定对照、消融、独立复验和论文。若期限紧，优先序列测试主线，服务端防御扩展可裁剪。

成果应包括：威胁模型与不变量、可执行状态规格、生成器/运行器/恢复器、独立判定器、版本化实验集、原始数据与分析脚本、重复实验结果、最小复现及修复、论文与答辩演示。每个研究结论链接相应版本和证据。

先保存课程版只读快照；经用户决定再创建毕设分支，保留两种目标与验收口径。新功能不把旧原生实验自动升级为同版通过，新增真实操作需先确认在授权范围内。
