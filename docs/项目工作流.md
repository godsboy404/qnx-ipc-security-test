# QNX IPC安全测试项目工作流

版本 0.1　日期 2026年10月15日

## 1 课程目标与项目边界

本工作流用于《专业综合能力提升》课程的QNX IPC安全测试项目，覆盖开题、规格、实现、实验、变更、交叉审查、恢复交接和个人能力证明。执行者为两名学生组成的项目组，另与一个独立两人组结对。教师负责选题、范围、评价规则和最终成绩的批准。

项目方向符合课程自选题的能力要求，但正式QNX实验须先通过授权、环境、目标和恢复四项前置门。当前可运行部分为主机模拟原型，QNX原生链路与隔离能力均待验证。目录建设和模拟测试不等于开题审批通过。

课程版选一个自建教学资源管理器，围绕一种自定义请求族开展边界、单字段和组合变异，建立基础验证、防御决策、异常观测和证据链。正常请求及已知不良样例必须都能运行或模拟，并能区分结果。

首版不做全系统MsgSend透明拦截、系统服务攻击、内核漏洞挖掘、覆盖率引导、机器学习检测、图形大平台或生产级安全证明。真实QNX执行仅限合法授权的隔离实验目标。

关键不变量：未登记目标不执行；防御拒绝的请求不转发；超时不直接判崩溃；没有独立探针不宣称隔离成功；模拟结果不能支持QNX实机安全或性能结论。

| 课程能力 | 本项目的可观察证据 |
| --- | --- |
| O1 人机责任 | 轮换分工、一次人工拒绝或修改AI建议的决策记录 |
| O2 工程契约 | Intent、稳定Req ID、GWT场景和验收矩阵 |
| O3 可信验证 | 同版本用例、原始结果、独立复核和失败轨迹 |
| O4 工程取舍 | 固定语料对照、成本、失败数据及ADR |
| O5 变化与对抗 | 批准Change、Finding、修复与回归 |
| O6 交接恢复 | 伙伴干净环境运行、重置与恢复记录 |
| O7 风险与个人能力 | 授权、数据边界、未知项及个人解释 |

## 2 工件链与责任分配

所有工作沿“Intent—Spec—Plan—Tasks—实现—证据—复核—新Intent”推进。每个阶段产物成为下一阶段输入。发现需求冲突、环境不支持或未知业务语义时，回到对应决策人澄清，保留理由，不由Agent静默修改承诺。

Intent记录原始问题、期望结果、影响对象、约束、不做内容、来源和未决问题。接受门输出Accepted、Rejected、Deferred等状态以及理由和责任人。当前项目Intent为Draft，教师接受状态待填写。

Spec说明可观察行为、范围、不变量与验收；Plan说明路线、影响和检查点；Task Card说明纵向小任务及完成证据。所有关键要求具有稳定ID，重大变化同步更新规格、测试、配置及验收矩阵。

| 角色 | 工作与责任 |
| --- | --- |
| 组员A | 第一轮实现，第二轮验证；分别保留代码和运行证据 |
| 组员B | 第一轮验证，第二轮实现；能够运行并解释改动 |
| 结对组 | 独立交付，审查2至3项关键Claim，提出有限变化与反例 |
| AI工具 | 起草代码、文档、候选测试和审查建议，报告未知 |
| 本组签署人 | 核查引用与事实，接受或驳回结论，声明范围 |
| 教师 | 批准范围、处理阻断与争议、复评个人能力和成绩 |

正式实验前冻结目标发布版本、环境和Fixture、契约版本、评价器版本及证据来源。原始运行文件写入新的run_id目录，禁止修改旧结果来体现新版本修复。

证据索引包括run_id、case_id、Req ID、源代码与配置版本、种子、实际发送长度、声明字段、策略决定、真实执行结果、探针来源、时间和成本。内容哈希用于完整性检查，执行来源仍需受控runner及人工复核。

每阶段说明以1至2页和3至5个关键链接为宜。无需重复抄写机器结果，review保存解释和签署，evidence保存运行事实。

## 3 阶段流程与质量门

下表是建议执行顺序和16周规划，不是老师已公布的课表。每个质量门通过后再扩大范围；环境问题持续两个教学单元仍不能形成切片时，缩小范围或换到教师提供的封装环境。

| 阶段 | 建议周次 | 输出与退出条件 |
| --- | --- | --- |
| G0 开题与授权 | 1 | 一页Brief、合法目标、两人轮换、教师接受状态 |
| G1 环境与合法路径 | 1至3 | qcc、架构、QNX镜像、恢复快照；合法请求可预测往返 |
| G2 规格与Harness | 3至5 | 字段模型、8项任务、验证命令、100次合法请求记录 |
| G3 变异与观测 | 5至8 | 三类变异、预算、重放、超时与进程异常分开记录 |
| G4 防御与基线 | 8至10 | 规则及基础限流；同语料防御前后对照，保留误拒 |
| G5 E1实验 | 10至11 | 原始逐次数据、成本、有限结论、ADR |
| G6 E2及E3 | 12至14 | 批准Change、冻结、Finding、修复及独立回归 |
| G7 交接与Defense | 15至16 | 干净环境复现、恢复、个人解释与签署 |

G1必须证明目标可重复运行、合法访问可行、快照能够恢复。当前终端未发现qcc或QNX环境变量；附件中的“工具链已配置”不作为该质量门已通过的证据。

G2以前先形成协议表，明确操作、声明长度、实际字节数、offset、flags和状态语义。底层可以选择devctl自定义命令；若使用直接MsgSend，必须先完成官方接口分发与封装契约。普通消息服务器不能自动等同于已实现的资源管理器。

G3以前准备外部watchdog和独立监控。TIMEOUT仅表示限定时间内无响应；CRASH需要退出状态、信号或其他独立证据；观测不完整时标为INCONCLUSIVE。

G4防御从ALLOW、BLOCK、RATE_LIMIT三个互斥路由决定开始；ALERT作为可附加事件。执行结果另列REPLY、ERROR、TIMEOUT、CRASH、UNKNOWN；避免把策略、告警和故障混为一类。

## 4 规格验收与任务拆分

规格版本为draft-0.1，以下是待教师确认的项目基线。每条MUST都应能追到场景、Task、测试命令和版本化结果。数字预算来自项目试跑，不作为QNX安全标准。

| Req ID | 承诺和最小验收 |
| --- | --- |
| SEC 01 | 未登记或撤权目标不执行；运行前及每次真实发送前检查 |
| IPC 01 | 合法请求返回批准结果；QNX门要求100次合法往返 |
| FUZ 01 | 三类变异可重复，同种子同协议生成相同语料 |
| SEC 03 | 拒绝非法类型、声明与实长冲突、非法offset与flags；拒绝不转发 |
| SEC 04 | 会话窗口与端点明确，超额限流，其他会话不连带限制 |
| OBS 01 | 用例、版本、配置、结果和来源关联完整，原始证据不改写 |
| ISO 01 | 崩溃与超时分开，隔离结论依赖独立完整探针 |
| REL 01 | 伙伴可启动、重放、重置和恢复；未实现项公开 |

实际文件采用SEC-01等带连字符的稳定ID。上表只为阅读排版省略连字符。

至少编写两条正向、两条负向、两条对抗GWT：合法ECHO、零长度合法请求、长度声明冲突、非法offset、组合非法字段、超额会话请求。每个Then同时关注响应、目标是否实际收到和证据是否生成。

任务按可验证切片拆为TASK-01至TASK-08：环境合法往返、规格与语料、发送与日志、独立探针、基础防御、实验取舍、Change与Finding、评价与交接。每张卡都记录输入、范围、不做、依赖、验收、负责人、DoR、DoD和停止条件。

章节02提出的至少一份ADR、5至8项任务、验收矩阵、状态或影响图、AI使用披露及未决问题，在本仓库分别落到对应文件。8条Not Ready红线仍适用，特别是无法执行的命令、无验证映射的MUST和伪装证据。

## 5 实验设计与指标口径

四场景分阶段实施。固定源版本、初始状态、语料文件、协议、输入顺序、环境、评价和预算；先证明功能与安全底线，再比较成本。每个场景建议至少3次Trial，保留逐次结果和失败，重复次数由教师与资源预算确认。

| 实验 | 主变量和结论范围 |
| --- | --- |
| EXP 01 | 合法请求正常基线，检查Harness与监控稳定性 |
| EXP 02 | 固定变异语料，无防御，建立异常基线 |
| EXP 03 | 与EXP 02逐字节相同语料，仅开启基础防御 |
| EXP 04 | 固定防御和预算，比较固定顺序与反馈调度；允许无收益 |

主机起步版实现四个模拟场景；EXP-04仅重排固定候选池，是反馈调度探索，不声称实现漏洞绕过搜索。自适应新样本或复杂异常检测属于可裁剪加分项。没有真实QNX执行时，不报告真实Crash率或性能开销。

统计单位为逻辑test case。normal与invalid标签由冻结协议及独立参考规则确定，不能直接把防御ALLOW当normal。语法非法不等于恶意攻击，语法合法也不代表安全。状态与频率另设情境标签。

| 指标 | 分子与分母 |
| --- | --- |
| 非法输入阻断率 | 已阻止转发的非法用例数 / 冻结非法用例数 |
| 正常误拒率 | 被拒绝或限流的正常用例数 / 正常用例数 |
| 非法放行率 | 实际允许转发的非法用例数 / 非法用例数 |
| 防御开销 | 相同负载下耗时和资源的增量；同时报告绝对值 |
| 隔离成功率 | 完整观测下成功隔离的确认故障数 / 完整观测的确认故障数 |

分母为零时返回null或N/A，并说明原因。隔离同时报告确认故障总数、完整观测数、成功、失败和未知；未知不能隐藏。Timeout样本保留在总体耗时中，成功子集另列。穿过网关不直接等于漏洞利用成功。

## 6 变化对抗与评价Agent

E1审查实验可比性、逐次结果和成本，最终决定采用、限制采用、保留Baseline或补充证据。每轮只选2至3个关键Claim，降低教师和伙伴负担。

E2采用CH-01候选：将每会话每1000毫秒最多10个结构有效请求缩小为5个，窗口定义为开左闭右，其他会话不受影响。教师批准后冻结Baseline，再修改配置、测试和说明。检查第5次允许、第6次限流、边界过期与会话独立。批准前只保留提案，不把它当课程既定要求。

E3采用两个受控方向：长度与实际载荷不一致等输入边界反例；证据材料中的诱导文字、假ID或错版本等评价边界反例。只对登记实验对象测试。确认阻断问题全部报告，课堂重点展示数量不限制披露。

Finding至少包括ID、目标版本、关联Req、前置、最小复现、预期与实际、原始证据、影响、分级、修复与回归及复核人。静态疑点标待验证，不能写成已成功越权或崩溃。

评价Agent最小流程：批准契约、版本索引检查、确定性检查、一次有限模型判读、输出校验、学生签署、伙伴回应、教师复评。当前工程实现确定性预检基线和K1至K6构造样例，尚未完成模型接入、真实材料校准和正式交叉审查。

| 输出状态 | 必要依据 |
| --- | --- |
| PASS | 同版本证据支持限定范围要求 |
| FAIL | 明确要求和可核查反例 |
| INSUFFICIENT EVIDENCE | 缺证据、错版本或未知，并列最小补查 |
| NOT APPLICABLE | 教师预先批准不适用 |

K1有效通过、K2明确反例、K3只有自述、K4诱导文字、K5虚假引用、K6批准不适用。通过六例不能外推为总体准确率100%。评价器不读取保留答案、不运行被评仓库任意代码、不修改对方实现、不写最终成绩。

## 7 交付交接与现场验收

六类交付内容分别放在Brief、Design、eval、evidence、release、review对应目录或索引中。文件名可调整，内容映射必须清楚。AI使用说明、风险与个人轮换记录贯穿各阶段。

现场先演示合法请求，再展示同语料无防御与有防御的结果及一个失败或未知，随后接受Change、伙伴质询、修复和恢复检查。QNX未验证时，演示标题和所有图表必须标明simulation，不能用主机模拟代替实机链路验收。

| 交接检查 | 通过证据 |
| --- | --- |
| 身份核对 | 发布版本、配置、Fixture、契约、评价器及来源一致 |
| 干净环境启动 | 伙伴依据README独立启动并运行测试 |
| 用例重放 | 同协议、配置和语料重现指定结果，保留新run_id |
| 故障与恢复 | 真实探针记录或明确标未实现，完成重置与恢复 |
| 个人能力 | 每人解释路径、完成有限修改、说明取舍与签署 |

150分钟压力验收只适用于已有切片：0至10分钟核身份，10至25分钟发布Change与影响分析，25至85分钟修改验证，85至105分钟交换审查，105至125分钟回应修复，125至145分钟复测恢复及个人问答，最后5分钟说明一个失败、改进和未知。时间为课程示范，需试跑调整。

Release Gate独立于学习成绩。关键安全边界不通过应修复、收缩范围或暂缓Release。项目篇45分工程成果、15分实验、15分评价器、25分个人能力是建议权重，须教师正式确认，不作为本仓库自行制定的成绩制度。

最终签署前回答：解决了什么问题，依赖哪些假设，哪些独立证据支持当前结论，哪里尚未验证，条件变化或失败时谁能接管。
