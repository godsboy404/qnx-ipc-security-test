## 复核步骤

1. 从仓库根目录执行 `python -m ipcsec.claim_audit --out review/claim-check-<新编号>.json`。命令只读已登记档案，报告使用新路径，失败时不写通过报告。
2. 核对 `configs/review-registry.json` 登记范围、来源版本和 Spec 草案身份；检查生成报告中 input_hashes 与 packet_sha256。原始档案位于 `evidence/native-fuzz-runs/20261017T122327Z-0b2f7718/`。
3. 独立复核者检查 `cases.jsonl`、`fuzz-results.jsonl`、`target-audit.jsonl` 及 `ipcsec/native.py` 的逐行重算逻辑。不要只接受报告中的布尔值；报告由项目自己的检查器产生。
4. 先独立填写下表，再查看模型答案和 AI 建议答案；分歧按“范围理解 / 缺少证据 / 逻辑错误 / 输出截断”分类。不能为了达到 3/3 而回填标签或修改旧结果。

## 下一次模型复测的准入条件

先完成独立人工判据复核，再冻结新的输入、独立答案、请求配置与预算。模型输入只含授权范围内的有限材料，独立答案留在评分侧。单次预先约定的批次结束后保留全部失败；不能把重复尝试中的最好一次当成独立校准。

本次仅增加本地判定报告和负例检查，不更改 Schema v2 请求、推理路由、输出上限或历史评分器。因此先前真实材料门未通过的状态继续保留；无需为本次文档与本地核验调用 API。
