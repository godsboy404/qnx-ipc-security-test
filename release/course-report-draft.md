# 面向QNX 8.0自建资源管理器的IPC对抗性测试与防御验证

课程报告草稿。组员：张润泽、陈卫吉；独立互评组：邓一帆（1人）。学号待填。教师已同意选题（2026-10-19用户转述，见review/teacher-approval-20261019.md）；两轮个人实现/交叉验证及签署由用户报告完成，最终课程结论签署另行跟踪。

## 问题与范围

项目研究可控教学资源管理器的输入处理、客户端防御和有界恢复行为。目标为自建/dev/ipcsec-lab，使用自定义devctl ECHO；应用头16字节，合法载荷0至64字节。声明长度、实际收到长度、offset和flags分别检查，不按异常声明长度分配内存。
不做全系统透明拦截、系统服务攻击、生产级安全或完整隔离证明。客户端网关可被具有直接设备访问权的程序绕过；会话编号是实验标签，不是可信身份。

## 实现与证据方法

主机模拟与QNX原生结果分开。原生Fuzzer固定种子、保留每个字段，默认128例、最多200例，实际变异载荷最多65字节。网关先查授权再校验输入，最后按每会话1秒最多10个合法尝试限流。
目标独立记录实际接收字节、PID、时间和顺序，主机oracle与客户端逐条核对。独立监督进程与只读OS探针分别观测生命周期和uname/proc检查。每轮使用新目录，保留源码/二进制/证据哈希；哈希用于一致性检查，不是第三方背书。

## 主要实验结果

| 场景 | 实际结果 | 解释 |
| --- | --- | --- |
| 合法IPC | 100 ping、1空载荷、重启后100 ping通过 | 证明所测路径正确往返 |
| 128例baseline | 34应答、94预期错误，转发128 | 非法输入由自建服务拒绝，不是漏洞利用成功 |
| 同语料defense | 94非法BLOCK、14合法RATE_LIMIT、20应答；目标接收20 | 限流与非法阻断分列；不把限流数量当误检模型准确率 |
| 24例限流专测 | 22应答、2限流，第二会话及窗口恢复正常 | 实时时钟场景；精确端点另由合成时钟校准 |
| 24例动态授权 | 两轮各8应答、16拒绝，恢复授权后放行 | 仅保证变更确认后的下一请求检查 |
| 受控SIGTERM恢复 | 前后各10应答，停机ENOENT，新PID恢复 | 主动终止，不是Fuzzer发现crash |
| 受控暂停超时 | 约2.002秒ETIMEDOUT=260，同PID恢复；21条接收记录 | 限专用gate检查点的发送侧超时，无多余延迟交付 |

具体run_id、manifest和范围见review/evidence-index.md、native-stall-milestone.md。历史实验可能来自不同源码版本；不能把它们拼成当前快照的一次统一实验。对照双方的源和二进制身份由比较脚本单独检查。
暂停实验126条只读探针记录，停止/重启回归43条，均仅支持所观测的操作和时间窗口。少量恢复时间是单次数据，不计算P95或宣称性能达标。

## 负结果与修复

保留一次限流语料计数错误及4轮暂停验收失败。暂停期间查询目标会阻塞监控，后续6秒兜底即使恢复服务也判FAIL；检查点后来限定为合法gate ECHO回复后、下一次接收前暂停，才完成新的验收。原始失败不改写成成功，见review/native-stall-issue.md。
