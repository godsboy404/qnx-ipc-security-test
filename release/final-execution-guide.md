## 先完成一次作者侧技术自检

在仓库根目录执行：

```powershell
python -m ipcsec.local_check run
python -m ipcsec.local_check verify --folder <上一步输出目录>
```

固定顺序：完整主机测试（当前81项，历史运行保留当时数量）、四场景模拟、确定性校准、单例重放、CH-01候选/回滚模拟、21例限流计数回归、本地Claim重验、历史证据审计。每项最多60秒，首次失败即停止，无自动重试、无API调用、无QNX故障操作。出现超时只记失败，不推断crash。

新目录 `evidence/local-check-runs/<run_id>/` 保存源文件身份、各项命令/耗时/退出码/合并日志、有限Claim报告、生成运行目录及manifest哈希。命令使用当前Python执行；当前环境须是自己信任的本项目源码。工具没有提供任意项目或命令执行接口，也不构成对陌生代码的隔离沙箱。

成功仅说明作者主机检查和历史档案复核通过，不代表新的QNX运行、模型校准、独立伙伴复现或正式E1/E2/E3。旧失败保留。新模拟数据与候选运行单独归档，并随交接包纳入核验。

## 个人能力练习卡

每人选一个实际修改点，由另一人提出验收条件并验证。以下是练习建议，不是预先完成的贡献：

* 限流解释与诊断：说明拒绝不延长窗口的业务含义，构造跨session与过期边界的最小序列，解释每次决策，保存自己的验证证据。
* 证据诊断：在临时副本中改动一项日志，解释是哪层检查拒绝，以及为什么“重写哈希”不能代替原始语义核验。禁止改原归档。
* 可恢复性解释：区分SIGTERM重启与SIGSTOP同PID恢复，指出2秒、6秒、15秒、45秒各自的作用，解释为什么有限探针不能证明全系统隔离。

个人实现须由本人实际完成一个经同伴提出并验收的小修改，不能把解释题当成实现贡献。每人按要求至少一次实现、一次验证；记录执行日期、修改前后、同伴意见和本人能解释的路径。
